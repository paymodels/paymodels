文档中心布局方案

在「左侧内容 + 右侧导航」框架下的 3 种设计方向

A

标准文档布局（推荐）

内容区居左（max-w-3xl），右侧固定 sidebar 列出所有文档页面链接。顶部有面包屑导航。移动端汉堡菜单展开 overlay 面板显示全部导航。

优势

  • 平衡内容阅读和全局导航
  • 用户随时知道自己在哪、还能去哪
  • 与现有 shadcn 组件体系无缝融合

劣势

  • 右侧导航可能较长
B

沉浸式阅读 + 页面目录

内容区更宽（类似 Medium），右侧只显示当前页面的目录（TOC）。全局导航放在页面顶部或独立导航栏。更适合长文章。

优势

  • 阅读体验最佳，无干扰
  • 长文章内跳转非常方便
  • 视觉上更现代、高端

劣势

  • 切换其他文档需要回到顶部
  • 对 FAQ 这种短内容页略显大材小用
C

双栏紧凑布局

左右两栏接近平分空间。右侧同时显示：全局文档列表 + 当前页面目录（分组展示）。信息密度最高，一眼看清全貌。

优势

  • 导航信息最完整
  • 适合内容不太长的帮助文档
  • 页面利用率最高

劣势

  • 内容区相对较窄
  • 视觉上可能较拥挤
